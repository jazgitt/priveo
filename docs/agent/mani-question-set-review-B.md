## B. Tech stack and architecture

| # | Question | Golden answer | Source | Decision | Notes |
|---|---|---|---|---|---|
| 21 | What is the app built with, and how does it handle state and navigation? | Flutter (iOS and Android) as one app for customer, crew and admin quick actions. Riverpod for state, go_router for navigation with one shell per role, and feature folders. | `docs/tech-stack.md` §1; `docs/architecture.md` §5 | Keep | |
| 22 | What are the rules between backend modules? | A module reads another only through that module's service interface, never its tables. `notifications`, `audit` and `media` are called and call nobody. `scheduling` is the only module that writes scheduled visits. Two modules never call each other in a circle: a domain event is used instead. | `docs/architecture.md` §4.2 | Keep | |
| 23 | How do the mobile app and the web portal authenticate? | Mobile: a short-lived bearer access token plus a refresh token tied to a server session. Web: an HttpOnly secure cookie, a CSRF token on every change request, and 60 minutes of inactivity (`ADM-ACC-12`). | `docs/architecture.md` §4.4; `docs/tech-stack.md` §2 | Keep | |
| 24 | How does the scheduler work? | Google OR-Tools CP-SAT behind an internal module. `solve(inputs) -> proposal` is a pure function with no database. The admin starts it, it runs as an in-process background task, and the result is a Draft schedule. Manual entries are fixed inputs on a re-run. | `docs/architecture.md` §4.7 and §10; `docs/tech-stack.md` | Keep | |
| 25 | How do crew uploads survive a poor connection? | Files go to a local queue (a Drift row), and `workmanager` uploads them in the background with retry. The app also resumes the queue on open, because iOS limits background work. The upload asks for a signed S3 URL, uploads, confirms to the API, then deletes the local copy. A job cannot complete until every required upload is confirmed (`CRW-SVC-10`). | `docs/architecture.md` §5.3; `docs/tech-stack.md` | Keep | |
| 26 | Which security findings are open, and which is High? | The only High finding is 3: media files are public and permanent (Vercel Blob with URLs that never expire). Medium: 4 no limit per IP on sign-in routes, 5 guessable crew passwords, 6 no security headers, 7 customer and crew sessions never expire. Also open: `CRON_SECRET` not set on the dev API, so the 8 scheduled jobs answer 503. | `docs/security-backlog.md` | Keep | |
| 27 | What conventions apply to time, money and API errors? | Times are ISO 8601 with offset on the wire, and the rules run in India Standard Time on the server. Money is integer paise with GST included. Errors use one envelope: `code`, `message`, `fields`, `request_id`. | `docs/architecture.md` §4.4 | Keep | |
| 28 | What is the hosting target, and what runs today? | The target is AWS Mumbai (ECS Fargate, RDS, S3, EventBridge Scheduler) with a private RDS. Since 29-Oct-2026 the API runs as two Vercel projects, `priveo-api-test` and `priveo-api-prod`, in Mumbai (`bom1`), each with its own Supabase PostgreSQL. The owner chose "Supabase first, then AWS Mumbai with a private RDS later", so the Supabase prod is interim. | `docs/architecture.md` §7.1; `docs/tech-stack.md` §1 | Keep | |
| 29 | What is the admin web portal built with? | React and TypeScript with Vite, TanStack Query and Table, React Hook Form with Zod, React Router, Tailwind with shadcn/ui, dnd-kit for the schedule board, Recharts for charts, an API client generated from OpenAPI, and Vitest, React Testing Library and Playwright for tests. | `docs/tech-stack.md` §5 | Keep | |
| 30 | What does the system component diagram show? | Clients: the Flutter app (role shells, feature folders, generated API client, secure storage, PostHog) and the React admin portal (HttpOnly cookie and CSRF). Both call one FastAPI service on Vercel (Mumbai) made of routers, domain modules, the OR-Tools scheduler, the Mani agent and 8 cron jobs. Data is Supabase PostgreSQL with pgvector. External: Resend, Vercel Blob, PostHog, Ollama (OpenRouter is configuration only), and FCM as a logging stand-in. GitHub Actions migrates, seeds and deploys. | `docs/system-component-diagram.md` | Keep | |
